# Roban S2S image integration

S2S is included by default in every Docker-capable image through `packagegroup-saha-docker-images`, so both the default full `robot` profile and `robot-docker` install the NVIDIA container runtime registration, the independent `saha-s2s` Compose project, and the local-only `roban-s2s:arm64` archive preload. The existing LiveKit Compose project remains unchanged. `kas/include/s2s.yml` remains available for custom image configurations that do not use the standard Docker packagegroup.

Before parsing/building `saha-s2s-container-image`, place a Docker archive tagged `roban-s2s:arm64` at `DL_DIR/roban-s2s.tar`. The recipe validates that the archive contains exactly one ARM64 image with that tag and never pulls from a registry. Place the four exact production speech artifacts listed by `saha-s2s-models.bb` under `DL_DIR/saha-s2s-models/`. That local-only recipe rejects missing or mismatched artifacts, extracts only the files consumed by the production adapter, and installs them exclusively into the factory-reset DATA image at `/data/models/s2s`; APP/rootfs packages contain no duplicate models. The generated relative `manifest.sha256`, `revisions.txt`, and `LICENSE.models` are verified during DATA image construction and again at service startup. APP-only upgrades preserve the DATA model tree; factory reset restores the pinned seed.

The service listens on configurable TCP port `SAHA_S2S_PORT` (default `8765`). It uses host networking because aiortc ICE host candidates require dynamic UDP sockets; this avoids pretending that a fixed UDP range exists in the Phase 2 backend. `ROBAN_S2S_ICE_SERVERS` accepts the backend's JSON STUN/TURN list. `/health` is liveness and `/ready` is model/runtime readiness. Compose explicitly selects `runtime: nvidia`; NVIDIA is registered but is not Docker's global default.

The production board profile uses only the pinned Chinese Sherpa KWS, Silero VAD, Paraformer STT, and VITS TTS assets recorded in `saha-s2s-models.bb` and mirrored in `scripts/s2s-benchmark/models.env`; benchmark-only candidate models are not packaged. The local LLM is Qwen2.5-1.5B-Instruct Q4_K_M at revision `91cad51170dc346986eccefdc2dd33a9da36ead9`, served by the pinned llama.cpp `b10156` CUDA ARM64 build. Install extracted model files under `/data/models/s2s`, llama.cpp under `/data/tools/llama.cpp`, and generate `/data/models/s2s/manifest.sha256` with relative file names. All paths must be owned by `10002:999`; directories and tools use mode `0750`, model files use `0640`. `saha-s2s-llm.service` binds only to `127.0.0.1:8081`, requires no API key, and is ordered before the S2S container.

No fixed rootfs increase is included before the S2S archive exists. Yocto's normal installed-size accounting includes the archive. During Phase 5, measure the archive, generated rootfs, and Docker unpacked size, then add only the observed safety margin to `kas/include/s2s.yml` if the target partition needs one; model sizes are excluded because models are post-flash assets.
